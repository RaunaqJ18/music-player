Connecting real Spotify data

This demo uses placeholder tracks — here's what it takes to wire in your actual account.
  1. Host this file yourself first (GitHub Pages, Vercel, Netlify, or a local dev server). Spotify won't authorize a request from this sandboxed preview — it needs a real URL to redirect back to.
  2. Create an app at the developer.spotify.com dashboard to get a Client ID. Since Feb 2026, the account creating the app needs an active Premium subscription, and new apps are capped at 5 authorized users in Development Mode.
  3. Add your page's URL as a Redirect URI in the app settings. For local testing use the loopback IP exactly — http://127.0.0.1:8888/callback — Spotify no longer accepts localhost.
  4. Implement Authorization Code with PKCE (no client secret needed for a browser app): generate a code verifier/challenge, redirect to accounts.spotify.com/authorize, then exchange the returned code for an access + refresh token.
  5. Request scopes user-read-currently-playing and user-read-playback-state. Poll GET /me/player/currently-playing every few seconds for track name, artist, progress, and album.images[0].url for the real cover art.
  6. For playback control (play/pause/skip) add user-modify-playback-state and call the matching /me/player/* endpoints. Actually streaming audio in-tab needs the Web Playback SDK and a Premium account.
  7. Spotify's API has no lyrics endpoint — pair it with a separate synced-lyrics source (e.g. an LRC-format API) matched by track and artist to drive the word-sweep highlight.
Once you have the access token, swap the demo tracks[] array in the script for live data, and replace the canvas "live art" with an <img> pointed at the real album art URL.
